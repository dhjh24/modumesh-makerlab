# Maker Studio UX Overhaul — Phase 2: Information Architecture (proposal)

Date: 2026-08-15 · Branch: agent/ux-ia · Status: **FOR REVIEW — no implementation yet**
Base: Phase 1 audit (docs/ux-audit-2026-08-15.md)

---

## 0. Locked architectural principle

> **Plugins remain the engine. They stop being the product UX.**

- A user thinks "I want to make a sign / bracket / logo / storage box", never "I need plugin X v1.0.0".
- The plugin registry, manifest schema, and worker pipeline stay untouched.
- A **Maker-Tool presentation layer** sits between the catalog API and every user screen.
- Target flow: **Create → Describe/upload → choose/refine concept → Studio → Check printability → Print/Export → My Models**
- Technical manifest info (engine, SDK version, MIME types, licenses, plugin IDs) moves behind a **developer/admin surface**, reachable only from Settings → Advanced → Developer.

## 1. The five primary destinations

| Destination | Route | Role | Replaces |
|---|---|---|---|
| **Create** | `/` | Default landing. Prompt-first: "What do you want to make?" | Home dashboard |
| **Studio** | `/studio/[projectId]` | Full 3D editing workspace; model dominates the screen | `/projects/[id]` editor |
| **My Models** | `/models` | Visual model library: thumbnails, state, open/duplicate/export/delete | (does not exist) |
| **Explore** | `/explore` | Maker-Tool catalog ("what can I make?") | `/generators` marketplace |
| **Settings** | `/settings` | Account + app config; **Developer/Admin is a nested, clearly separated area** | (does not exist) |

Supporting routes (outside the five):
- `/login` (+ `?mode=register`, `?next=`)
- `/studio/[projectId]/compare` — compare lives inside Studio as a mode, not a separate destination
- `/admin/*` — developer surface (plugin registry, resync, submissions, health)
- `/api/health` — unchanged (server probe)

## 2. Route map — old → new (with compatibility)

| Old route | New route | Compatibility |
|---|---|---|
| `/` (dashboard) | `/` (Create) | same URL, new content — no redirect needed |
| `/projects/[id]` | `/studio/[id]` | **permanent redirect** 301 (keep `/projects/[id]` working during transition, then rewrite) |
| `/projects/[id]/compare` | `/studio/[id]/compare` | redirect |
| `/generators` | `/explore` | redirect (both directions; `/generators` kept as alias) |
| `/generators/[plugin]` | `/explore/[tool]` | redirect; tool slug derived from plugin_id (stable) |
| `/health` | `/admin/health` | redirect; removed from primary nav |
| — | `/models` | new |
| — | `/settings` | new |
| — | `/admin/*` | new: `/admin/plugins`, `/admin/plugins/[id]`, `/admin/submissions`, `/admin/health` |

Redirects implemented as Next.js `redirects()` (301) — old URLs never 404 during the transition.

## 3. Navigation

### Desktop (header)
```
[ModuMesh MakerLab]   Create · Explore · My Models      [Account ▾]
                                                         ├─ Settings
                                                         ├─ Developer (admin, role-gated)
                                                         └─ Logout
```
- **Create** = primary (brand-adjacent, visually emphasized)
- **Studio is not in the nav** — it's a contextual workspace you enter from Create/My Models (breadcrumb: `Create → Studio: "Storage box"`)
- **Health is removed from nav** (was the biggest ops leak)

### Mobile
```
[ModuMesh MakerLab]                          [Account]
[Create] [Explore] [My Models]   ← bottom tab bar (thumb-reachable)
```
- Bottom tab bar: Create / Explore / My Models / More(Settings+Admin)
- Studio on mobile = full-screen workspace with its own tab row (Parameters / Model / Info) — same pattern as today's editor, re-skinned

## 4. Page responsibilities

### 4.1 Create (`/`) — "What do you want to make?"
- **Hero prompt**: large input `Describe the object you want to create...` + example starter chips (Nameplate, Storage box, Wall bracket, Phone stand, Organizer, Sign, Keychain)
- **Creation modes** (cards, not plugin IDs):
  - Text → 3D (AI; **gated — not production-ready until a real provider ships**)
  - Image → 3D (AI; gated same)
  - Parametric Builder (→ Explore picker of parametric Maker Tools)
  - Upload Model (→ Studio with an imported mesh; **requires a new upload endpoint** — backend gap)
  - Remix Existing Model (→ My Models picker)
- Empty state (first visit): friendly intro "Make your first thing" + 3 example tools
- Loading: skeleton cards; Error: retry + offline state (reuse existing state views)

### 4.2 Studio (`/studio/[id]`) — the centerpiece
```
┌─────────┬──────────────────────────────┬───────────────┐
│ LEFT    │ CENTER                       │ RIGHT         │
│ parts   │ 3D viewport (dominates)      │ parameters    │
│ tree    │ orbit/pan/zoom               │ grouped by    │
│ history │ grid/build plate             │ Dimensions    │
│ add     │ bbox/dims overlay            │ Shape/Text    │
│ part    │ ortho/perspective            │ Mounting      │
│         │ wireframe/reset/fit          │ Print settings│
│         │                              │ Advanced      │
├─────────┴──────────────────────────────┴───────────────┤
│ BOTTOM: validation · dims · triangles · volume ·        │
│ print estimate (when real) · [Print / Export]           │
└─────────────────────────────────────────────────────────┘
```
- Loads the latest terminal job's model; **regenerate** = re-run the same tool+parameters (existing job pipeline; new idempotency key per click)
- Compare = a Studio mode (modal/page) — "Try another maker tool with the same input"
- States: no model → empty prompt w/ actions; loading → skeleton + staged progress text; error → panel with recovery (retry/repair/open in new)
- **Export lives here as the primary bottom-right action** (see §7)

### 4.3 My Models (`/models`)
- Card grid: thumbnail (first viewable output, GLB render or STL preview), name, maker tool name (not plugin_id), last modified, printable state (PASS/WARNING/FAIL/unknown)
- Row actions: Open (→Studio) · Duplicate (new project) · Export · Delete (new API needs — today only archive exists; **backend gap: DELETE + duplicate**)
- Filters: All / Printable / Needs work / AI-generated
- Empty: "No models yet — start with a nameplate" + CTA
- Loading: card skeletons; Error: retry/offline

### 4.4 Explore (`/explore`) — Maker Tools
- Grid of **Maker Tools** (presentation-layer objects, see §6), each: icon, name, one-line promise, category, difficulty (Beginner/Intermediate/Advanced), preview image when available
- Categories (user-facing, from existing plugin categories): Signs & Labels · Storage & Organization · Brackets & Mounts · Decorative · AI (gated) · Repair & Check
- Filters: search + category + difficulty (no maturity/engine/license filters — those are admin)
- Tool detail (`/explore/[tool]`): promise, example uses, input mode, "Open in Studio" CTA + parameter preview — **no SDK/MIME/license/engine dump** (that content exists on `/admin/plugins/[id]`)
- Empty: "More tools coming" + submit-a-tool CTA (community submissions exist in the API)

### 4.5 Settings (`/settings`)
- Account: display name, email, password (backend: auth/me + register; **password change is a backend gap**)
- App: units (mm default), default printer/build volume (stored client-side; **backend gap if shared across devices** — MVP: localStorage)
- **Developer / Admin** (role-gated by existing `require_admin`): plugin registry (resync/enable/disable/sign/quota), submissions, health, audit allowlist — the ONLY place plugin IDs, versions, licenses, SDK details appear
- States: loading skeleton, save success/error inline

## 5. Maker-Tool presentation layer (Phase 8 forward-contract)

A `MakerTool` is derived from the catalog item + manifest but is the ONLY object user screens read:

```ts
interface MakerTool {
  slug: string;                 // stable, from plugin_id (used in URLs)
  name: string;                 // "Nameplate Maker" — never "nameplate"
  promise: string;              // one-line user benefit
  category: 'signs' | 'storage' | 'brackets' | 'decorative' | 'ai' | 'repair';
  icon: string;                 // emoji or bundled icon
  previewImage?: string;        // thumbnail when the plugin ships one
  difficulty: 'beginner' | 'intermediate' | 'advanced';
  inputMode: 'text' | 'image' | 'parametric' | 'upload';
  parameterGroups: GroupedField[];  // schema fields grouped for Studio
  outputFormats: string[];      // user names: "STL, GLB" (not MIME strings)
  capabilities: { preview: boolean; regenerate: boolean; printCheck: boolean; ai: boolean };
  productionReady: boolean;     // false hides AI stubs from normal screens
}
```

## 6. Empty / loading / error state contract (all destinations)

| State | Pattern |
|---|---|
| Empty | Icon + one-line what-this-is + primary CTA + (optionally) example chips — never dev copy ("install plugins") |
| Loading | Skeleton cards/panels; Studio generation uses **staged messages** (Preparing → Generating geometry → Processing mesh → Checking model → Creating preview → Ready) instead of raw statuses |
| Error | Friendly message + recovery action (Retry / Repair / Open in Studio / Back to Create) + expandable technical detail for support (existing ErrorPanel pattern) |
| Offline | Existing OfflineState with retry |
| Unauthenticated | `/login?next=` redirect (existing pattern) |
| Disabled capability | Tool card shows "Coming soon" for AI stubs; print-check row shows "Not run" rather than claiming PASS |

## 7. Print/Export (forward contract, Phase 5/6)

- One primary bottom-bar action in Studio: **Print / Export**
- Dialog shows: model dimensions · units · validation result (real checks only) · file format choice (3MF preferred when produced, else STL/GLB) · generated version (tool name + version, user-readable)
- **Never fabricate** slicing estimates or printability claims not backed by mesh-inspector/slicer output
- Interface boundary stubbed for a future slicer integration (existing slicer plugin + slicing-report.json are the real source)

## 8. Backend gaps this IA depends on (recorded, not built here)

1. **Model upload endpoint** (Create: Upload Model, logo-lightbox currently takes base64 text) — multipart upload + artifact ingest
2. **DELETE project/model** and **duplicate project** (My Models actions; archive exists only)
3. **Password change** (Settings) — no endpoint today
4. **Thumbnails** — viewer-rendered client-side initially (no server thumbnails needed for MVP)
5. **AI provider boundary** (Phase 9) — provider interfaces so Text/Image→3D can be added without UI changes

## 9. Implementation waves (post-approval, each a small PR)

- **W2.1**: Route scaffolding — redirects (`/projects/*`→`/studio/*`, `/generators`→`/explore`), new nav (Create/Explore/My Models/Settings), Health → /admin/health, empty-state copy pass
- **W2.2**: Explore page as Maker-Tool grid + tool detail (presentation layer, no dev data)
- **W2.3**: Create landing (prompt + modes + starter chips; AI modes gated/hidden)
- **W2.4**: My Models library (cards, states, open/export; duplicate/delete after backend lands)
- **W2.5**: Studio re-skin (left tree/right grouped params via SchemaForm `x-group`, bottom bar with staged progress + Print/Export dialog)
- **W2.6**: Settings + Admin surface split
- Then Phase 3: UX flows/wireframes for Create wizard + Studio interaction details
