# Maker Studio UX Overhaul — Phase 1: Product/UX Audit

Date: 2026-08-15
Branch baseline: `main` @ 0e4f20f (GM-10/11/12 merged)
Scope: apps/web, packages/ui, packages/viewer, packages/shared-types (frontend only; API surface listed for reference)

---

## 1. Complete route inventory

| Route | File | Auth | Purpose |
|---|---|---|---|
| `/` | pages/index.tsx | required | Home dashboard |
| `/login` (`?mode=register`, `?next=`) | pages/login.tsx | public | Sign in / create account |
| `/generators` | pages/generators/index.tsx | public | "Generator Marketplace" catalog |
| `/generators/[plugin]` | pages/generators/[plugin].tsx | public | Generator detail page |
| `/health` | pages/health.tsx | public | System health table |
| `/projects/[id]` | pages/projects/[id].tsx | required | Project editor (the de-facto Studio) |
| `/projects/[id]/compare` | pages/projects/[id]/compare.tsx | required | Compare generators (JSON payload editor) |
| `/api/health` | pages/api/health.ts | — | Next.js health probe (server) |

No other routes exist. There is **no My Models, no Settings, no admin UI, no Create wizard, no Explore destination** — the app is a thin dashboard + one editor page.

## 2. Current navigation

`AppShell` (components/AppShell.tsx) renders a top header with exactly three links:

- **Home** (`/`)
- **Marketplace** (`/generators`)
- **Health** (`/health`)

Plus a sign-in/account chip (display name or email + Logout). Footer: *"Self-hosted generators · schema-driven · no CAD in the request path"* — developer copy.

**Finding: Health (an ops page) sits in primary nav; there is no Create/Studio/My-Models destination.** Navigation labels are developer-oriented ("Marketplace" = plugin catalog framing).

## 3. Primary user flows (as they exist today)

### 3.1 Onboarding
`/login` → email/password (or register with display name) → token in localStorage → redirect to `?next` or `/`.

### 3.2 Create → Generate
Home (dashboard) → "Create project" form (name + description) → **must type a name before anything else** → lands in `/projects/[id]` with empty state → pick a generator from a dropdown showing `name (v{version})` → schema form renders every parameter → "Generate" → job queues.

### 3.3 Generation progress
Bottom status bar: `Status` badge + progress bar + raw `{status} — {progress_message} ({pct}%)`. Polls every 1s via `useJobPolling`. On terminal: file list refreshes, first viewable file auto-loads into the viewer, `JobResultPanel` mounts.

### 3.4 Preview
Blob-URL fetch with bearer token → `ModelViewer` (STL/GLB) → orbit/zoom/pan, wireframe, build plate, bounding box, dimensions readout, reset camera, gizmo.

### 3.5 Export
Files list in the right column → click a file → blob download with real filename (Content-Disposition parsed). **No 3MF/format preference, no Print/Export primary action.**

### 3.6 Project/model management
- Rename/describe in editor ("Save project")
- Version history = job list (`job_type #attempt_number`, status badge)
- **No duplicate, no delete, no archive UI** (API has `POST /projects/{id}/archive` — unused)
- **No thumbnails anywhere**; Home lists projects as text rows

## 4. Developer-oriented UI leaking into normal workflows

1. **Nav labels**: "Marketplace", "Health" — plugin/ops framing
2. **Home copy**: *"Pick a generator, tune parameters from its schema, queue a job, and inspect the result."*
3. **Plugin IDs everywhere**: dropdown options are `name (v1.0.0)`; catalog cards show `plugin_id@version`, engine, license SPDX, maturity badges (experimental/stable/deprecated)
4. **Generator detail page** exposes: engine, output formats (MIME strings), timeout seconds, memory MB, SDK version, capabilities list, tags — a developer manifest dump
5. **Compare page** is a raw **JSON textarea** for the input payload — deepest dev-leak
6. **Fixture STL / Fixture GLB buttons** in the project editor header — test fixtures in a normal workflow
7. **Version history copy**: "Each job attempt is an immutable version of this project."
8. **Files panel**: raw `content_type · KiB` and filenames like `design.json`, `slicing-report.json`
9. **Footer**: self-hosted/schema-driven/no-CAD copy
10. **Empty states** mention "Install plugins", "resync the registry", "Submit a generation from a project editor"

## 5. Confusing terminology for ordinary users

`plugin`, `generator`, `marketplace`, `schema`, `job`, `attempt`, `version`, `maturity`, `engine`, `SDK version`, `input payload`, `content_type`, `KiB`, `correlation_id` (in error technical details — good for support, noise for users), statuses `queued/running/validating/uploading`.

## 6. Unnecessary settings / dead UI

- **Health page in nav** — ops, not user-facing
- **Compare page** — advanced/dev; hidden behind a secondary button, but the JSON editor is unusable for ordinary users
- **Pricing & shop panels** (in JobResultPanel) — pricing gated on `material_estimate` (only logo-lightbox produces it), shop handoff returns 400 unless completed — visible as dead/erroring UI for most generators
- **Fixture buttons** — test-only

## 7. Model generation flow — gap analysis vs mission

| Mission step | Current state |
|---|---|
| Describe it | ❌ No prompt entry. User must know a plugin exists and pick it by name |
| Generate it | ✅ Queued job flow works, but with raw statuses, not staged messaging |
| Adjust it | ⚠️ Parameters exist (schema form) but regeneration = re-submit with a new idempotency key; no "regenerate" affordance per se |
| Check it | ❌ No printability panel. `mesh-inspector` plugin exists but **nothing in the UI surfaces it** |
| Print it | ❌ No Print/Export action; raw file list only |

## 8. Preview / export flow detail

- Preview: `fetchFileBlob` → blob URL → viewer; GLB via `useGLTF`, STL via `STLLoader`; auto-load first viewable file on completion
- Viewer capabilities: orbit, zoom, pan, wireframe toggle, build plate grid, bounding box, dimension readout, reset camera, gizmo, reduced-motion support — **solid foundation**
- Missing vs Phase 4 spec: ortho/perspective toggle, fit-to-view (has `Bounds fit` on load), model centering (has `Center` on load), dimension display is in the status strip only (not overlay), no per-part tree
- Export: `content-disposition` filename parsing works; **no format choice, no validation summary attached**

## 9. Project/model management — gap analysis

- **No "My Models" library**: Home is a 12-item text list, no thumbnails, no printable-state badge, no duplicate/delete
- Archive API exists but has no UI
- No search over models (API supports project list only)
- No model-level entity in the UI: models live inside project→job→files chains

## 10. Mobile behavior

- Single breakpoint `@media (max-width: 960px)`: grid collapses to 1 column; editor becomes tabbed (Parameters / Preview / Project / Files)
- Tabs are functional but styling-only; header nav is not collapsed (no hamburger) — 3 links fit, but with user chip it crowds on small phones
- Viewer min-height 360px on mobile
- No touch-specific affordances beyond OrbitControls defaults; no device-orientation handling
- A11y baseline is good: skip link, aria-live status, labeled inputs, axe e2e gates

## 11. UI kit inventory (packages/ui)

`Button`, `Badge`, `JobStatusBadge`, `ErrorPanel`, `SchemaForm` (schema-driven, supports enum/number/boolean/string + validation + units), `LoadingState`/`EmptyState`/`OfflineState`/`RetryState`.

- `SchemaForm` is the crown jewel: **schema-driven rendering already exists** — Phase 8's "no hard-coded forms" invariant is already satisfied. It renders raw schema keys when no `title`; grouping (Dimensions/Shape/Text/…) does **not** exist yet (needs `x-group` support).
- No tooltip/modal/stepper/dialog/card-grid primitives — will need additions for wizard + model library.

## 12. Viewer inventory (packages/viewer)

`ModelViewer` (STL/GLB, toolbar: reset camera/wireframe/build plate/bounding box, dimensions callback, gizmo, reduced-motion, error callback), `math.ts` (box→dims), `types.ts`.

Missing for Phase 4 Studio: ortho/perspective, fit-to-view button, explicit centering control, dimension overlay, grid toggle separate from build plate, build-volume overlay, triangle/volume stats (available from design.json when produced).

## 13. Backend capability vs UI coverage (what exists but has no UI)

| API | Status |
|---|---|
| `POST /projects/{id}/archive` | no UI |
| `POST /plugins/resync`, `admin/plugins/*` | no UI (admin) |
| `POST /submissions/validate`, `security-scan` | no UI (community plugins) |
| `POST /shop/submit-order` | no UI |
| `mesh-inspector` plugin (manifold/printability analysis) | **no UI** |
| Upload (image/model input) | ❌ **no upload endpoint or UI at all** — logo-lightbox takes base64 in a text field (max 1MB) |
| AI generators (triposr/hunyuan3d) | manifest-only stubs, no plugin.py — must not be surfaced as production-ready |

## 14. Summary of highest-impact findings

1. **No creation entry point** — the "Describe it" step doesn't exist; users must understand the plugin model
2. **Developer UI leaks everywhere** — plugin IDs, versions, MIME types, JSON payload editor, fixtures, health page, ops copy
3. **No model library** — projects are text rows; no thumbnails, no duplicate/archive/delete, no "My Models"
4. **No printability surface** — mesh-inspector exists backend-side, zero UI
5. **No unified export** — raw file list instead of Print/Export with format choice + validation summary
6. **Compare page is unusable for non-devs** (raw JSON)
7. **Generation progress is raw statuses** — no staged human messaging
8. **SchemaForm lacks grouping** — every generator parameter dumps flat, no Dimensions/Shape/Text grouping
9. **No Settings/Admin separation** — admin APIs exist, no UI anywhere
10. **Mobile is a collapse, not a design** — tabbed panes, no nav collapse

## 15. What to preserve (do not rewrite)

- `SchemaForm` + `defaultsFromSchema` + validation (schema-driven rendering is the right architecture)
- `ModelViewer` capabilities and blob-URL auth pattern
- `AppShell` a11y scaffold (skip link, aria-live, labeled nav)
- State views (Loading/Empty/Offline/Retry) and ErrorPanel
- API client shape (`api` object, `apiFetch`, `fetchFileBlob`)
- Job polling (`useJobPolling`) and auth hooks
- The queued-generation pipeline, plugin SDK, MinIO artifact model — untouched by UX work
